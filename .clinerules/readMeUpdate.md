# README Update Rule

When making changes, update `readme.md` **only when** the change affects how someone uses, sets up, or understands the mental model of the project.

## Required README updates
Update the README when any of the following happen:
- A new feature or major capability is added
- Setup, installation, or development commands change
- New scripts are added that users need to run
- Environment variables or configuration requirements change
- Project structure or architecture changes in a meaningful way
- Breaking changes are introduced

## Do NOT update the README for
- Bug fixes
- Internal refactors
- Adding or updating tests
- Styling or minor UI changes
- Performance improvements with no usage impact

## How
- Edit only the relevant section. Testing, Deployment, and Developer Instructions belong in the "Getting Started" subsections currently marked "Reserved for 191".
- Never rewrite the whole file.
